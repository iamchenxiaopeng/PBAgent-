## 开场：两个极端的痛（2 分钟）

〔开场不放代码，放一张两列对比表〕

大家好，今天讲的项目叫 PBAgent，一句话：**给浏览器自动化装上"便宜的那只手"**。

先说我们想解决的问题。浏览器自动化这件事，现在有两个极端，都有病：

| 方案 | 成本 | 稳定性 | 页面改版后 |
|------|------|--------|-----------|
| 传统 RPA 脚本 | $0 | 高 | **直接挂，人工修** |
| 纯 LLM Agent | 高（每步推理） | 低（随机性） | 天然适应 |

写过脚本的同学都知道第一种痛：页面改个版、按钮改个名，脚本就死给你看，然后半夜被叫起来修。
第二种是这两年才有的痛：让 AI 看屏幕操作，什么都能干，但**每一步都要调一次大模型**，一个 20 步的任务就是 20 次多模态调用，而且每次决策有随机性——今天能跑明天挂，审计同学看了直摇头。

关键洞察是这张表里藏着的：**真实业务里 90% 的运行是稳定流程**——改价、对账、导报表，页面天天一个样；只有 10% 的时间在遭遇页面改版。

那问题来了：**为什么要为 10% 的改版场景，付 100% 的持续成本？**

PBAgent 的答案是把成本结构反转：稳定的时候一分钱不花，改版的时候花一次钱自愈，自愈完**把经验存下来**，又回到一分钱不花。LLM 的成本是**脉冲式的**，不是持续性的。

〔停顿一拍〕

这就是今天的主线。接下来 30 分钟讲清楚四件事：这个系统怎么设计、核心代码怎么写的、实测数据长什么样、以及最后现场让它当众挂一次给大家看。

## 第一幕：三态模型——四个字母讲完全部架构（5 分钟）

〔放三态模型图〕

整个系统就四个状态，我逐个走：

**STATE A，Playbook 确定性执行。** "已知流程"用 YAML 描述，叫 Playbook。14 种步骤类型——goto、click、fill、assert、loop 这些，由 Playwright 确定性执行。**零 LLM 调用，零成本**。选择器是多层降级的：css 挂了试 xpath，xpath 挂了试 text——text 是人类语义，改版存活率最高。

**STATE B，LLM Agent 兜底。** A 挂了——通常是 E1，元素定位失败——就唤醒 Agent。它每轮做三件事：感知（截图 + DOM 压缩摘要）、决策（LLM 输出一个 JSON 原子动作）、执行。8 种动作：click、fill、press、goto、wait、drag、done、fail。它是个救火队员，不是常驻员工。

**又回到 STATE A，恢复点续跑。** Agent 每做一个动作，系统就检查当前页面是否命中了 Playbook 后面某一步的特征——命中了就把 Agent "退货"，从那一步断点续跑。**AI 只救火，不接管整栋楼**。

**STATE C，沉淀。** 救火成功的轨迹被"蒸馏"成新版 Playbook 草稿：失败步骤原位替换，前后步骤保留。人看完 diff、promote，下次这个流程又是 $0 跑通。

〔指图〕

稳定运行在 A，出事走 B，救完回 A，经验进 C。**A→B→A→C**，请大家记住这四个字母，后面演示就是走这条路。

这里有一个重要的设计判断：**为什么 Agent 是"每步决策一个动作"而不是一次规划全链路？** 因为单步可审计——每一步的输入输出截图全留痕，失败可隔离；长链路 ReAct 式规划一旦中间某步漂了，后面全错。

## 第二幕：核心实现——三段值得抄的代码（8 分钟）

〔这幕是给工程师的，投影直接开代码〕

### 看点一：恢复点评分制——Agent 救完火怎么"退货"（`src/recovery/fingerprint.ts`）

Agent 每做完一个动作，要回答一个问题：**当前页面像不像 Playbook 后面的某一步？**

做法是给每个候选步骤算特征分：

```text
URL 命中      +30 分
selector 弱匹配 +50 分
关键文本命中   +20 分
```

规则：**总分 ≥ 50 且是唯一最高分**才算命中，只看失败步之后 5 步的窗口（防止匹配回已经走过的页面）。

这里有个开发中才发现的设计缺口：纯 assert 步骤（只声明了 textContains）上限只有 20 分，**永远过不了 50 分的阈值**——纸面设计推演不出来，跑了真实用例才暴露。补的规则是：assert 的候选文本命中直接给 50。教训：**评分阈值这种设计必须用边界用例验算**。

### 看点二：轨迹蒸馏——不是录制，是提纯（`src/learner/distill.ts`）

Agent 自愈轨迹转 YAML，最容易犯的错是"原样转录"。我们的蒸馏规则：

```typescript
// 密码框不沉淀：登录流程属于 include 子流程，混进业务步骤会泄露凭证结构
if (act.action === 'fill' && step.target.type === 'password') return null;

// drag 不沉淀：拖滑块是反爬对抗，重放时对着正常页面拖动毫无意义
if (act.action === 'drag') return null;

// 值回填：fill 的值和某个参数相等 → 保留插值形式
const matched = Object.entries(params).find(([, v]) => String(v) === act.value);
value: matched ? `\${params.${matched[0]}}` : act.value,
```

三条规则各挡一类脏数据：**密码框不沉淀**（安全）、**drag 不沉淀**（语义）、**参数值回插值**（复用性）。还有一条关键的：v2 会**剥离 include**——因为蒸馏输入是展开后的步骤，保留 include 字段会导致登录被二次展开。

产出物长这样〔放 v2.diff.md〕：

```text
07. ~ 替换（原步骤 7）
       - 旧: [fill] 填新价格 · #price = ${params.price}
       + 新: [fill] 填值 · #price = 199
08. + 新增 [click] 点击「确认下单」 · button.btn-save-v2 · 弹窗:accept
```

注意第 8 步的 `弹窗:accept`——Agent 救火时处理过 confirm 弹窗，蒸馏时自动把这个知识写进新版本，下次 Playbook 直接带上。**这就是"经验沉淀"落到字段级的样子。**

### 看点三：click 三级降级链——真实站点教我们做人（`src/agent/loop.ts`）

```typescript
try {
  await el.click({ timeout: 5_000 });            // ① 正常点击
} catch (e) {
  const blocked = msg.includes('intercepts pointer events') || ...
  if (!blocked) throw e;
  try {
    await el.click({ timeout: 1_000, force: true }); // ② 强制点击（跳过 hit-test）
  } catch {
    await el.dispatchEvent('click');                 // ③ JS 派发
  }
}
```

背景是一个真实站点的血案：Playwright 日志显示元素 **visible、enabled、stable** 三绿，但点击 23 次重试全部失败——因为有个容器元素把指针事件拦截了。**Playwright 的"元素可用三件套"根本不包含"能收到指针事件"这第四项**。三级降级链就是给这个场景准备的。

这段代码想传达的编码约定：**凡是跨外部资源的调用，显式设超时 + 备好降级路径，不要相信默认行为**。我们真实站点踩的三个坑——执行上下文销毁、模型吐非 JSON、截图卡字体加载 30 秒——病根全是"相信了默认行为"。

## 第三幕：实测数据（3 分钟）

〔放数据表，逐行讲〕

qwen3.8-max 实测：

| 场景 | LLM 调用 | Tokens | 成本 | 耗时 |
|------|---------|--------|------|------|
| STATE A 稳定运行（50 SKU） | 0 | 0 | **$0** | 22.6s |
| 沉淀后 v2 重跑 | 0 | 0 | **$0** | **2.6s** |
| A→B→A 自愈一次 | 2 | 8,744 | **$0.0417** | 112.9s* |
| 纯 Agent 全链路（登录+改价） | 8 | 15,438 | $0.0276 | 18.7s |

*自愈那次 112 秒里 Agent 只走了 2 步，大头是感知器截图和思考型模型的输出——输出 token 是输入的近两倍，思考型模型输出贵 4 倍，这是成本主因。

三个数字请大家记住：**稳定跑 $0，自愈一次 4 分钱，沉淀后重跑 $0 且快 9 倍**。

换个算账方式：一次自愈 $0.04，换回一条**再也不需要人工修**的 Playbook。按"改版一次摊销"计算，LLM 成本可以忽略。

另外工程质量：**114 个测试全绿**（单元 + 真实浏览器 E2E），Playbook 加载 3ms/次，十次运行一致率 100%。

〔如果被问 deepseek-flash：W9 换了模型，同场景成本再降一个量级到 $0.0007——单价差异不是 token 差异。可见成本模型对模型单价敏感，CostTracker 按模型分价记账就是为这个〕

## 第四幕：现场演示（8 分钟）

〔提前按清单检查过三服务。开场先说：所有东西跑在我本机，三服务：演示站 3456、后端 4567、控制台 5173〕

### Demo 1：零 LLM 跑流程（2 分钟）

现在我把 Playbook 换回 v1——一个**故意保留的旧版本**，它的"点保存"步骤找的按钮叫"保存"。

## 第五幕：真实站点踩坑——模拟环境验证架构，真实环境验证细节（6 分钟）

〔这幕讲故事，语速可以放慢〕

前面所有演示跑在自研的 test-site 上。W8 结束时我们去打了真实站点，连续踩了三个坑，每个都值得说：

**坑一：点击触发导航，执行上下文直接销毁。** 报错 `Execution context was destroyed`，任务判死。本地为什么测不出来？因为 test-site 几乎不跳转，这个路径从未被激活。修法是感知器整批采集包一层退避重试——这类崩溃是**竞态**不是**错误**，断言测不出来，只能重试兜底。

**坑二：模型不吐 JSON，改吐自家的工具调用标记（DSML）。** DeepSeek 思考模式偶发输出 `<｜｜DSML｜｜ invoke...>` 这种私有格式。修法是三层防御：请求侧 `jsonMode` 压格式、解析侧兼容 DSML、失败把**坏输出原样回传**让模型自我纠正（比单纯重发请求有效得多）。

**坑三：截图卡在 `waiting for fonts to load` 30 秒。** Playwright 截图默认等字体加载完成，**且这个等待没有参数可以关**。真实站点外部字体 CDN 慢就挂满 30 秒。修法：超时压到 6 秒 → 超了走 CDP 直取（50ms）→ 再不行空截图退化纯 DOM 决策。

〔停顿〕

三个坑，一个病根：**相信了默认行为**。默认无重试、默认输出 JSON、默认 30 秒超时。所以现在的编码约定是：凡跨外部资源的调用，**显式超时 + 降级路径**，一行都不能省。

**最后一个故事，反爬。** 我们让 Agent 去百度搜索，必被拦到验证码页。排查时做了三组对照实验：

| 路径 | 结果 |
|---|---|
| 冷启动直接访问结果页 URL | ✅ 正常 7 条结果 |
| 先访问首页再搜索 | ❌ 验证码 |
| （复测）冷启动直连 | ✅ 正常 |

真凶不是指纹，是**首页 cookie**——风控标记挂在 cookie 上不挂 IP。所以最有效的自愈是：感知到验证码页就**清空 cookie**重新访问，零 token 成本。配合 stealth 指纹擦除、拖拽动作（ease-out 曲线+抖动模拟真人）、以及提示词层面的"搜索站直接 goto 结果页"，最后百度任务 3 步 10.3 秒 $0.0038 跑通。

这故事的方法论：**反爬问题先做入口路径对照实验再动代码**，以及**自愈优先用确定性手段**（清 cookie），别一上来就让 LLM 猜。

## 收尾：三句话带走（3 分钟）

〔放总结页〕

第一句：**A→B→A→C**。已知流程确定性跑（$0），失败 LLM 兜底（$0.04），恢复点接回主线，经验蒸馏沉淀（下次又 $0）。LLM 成本是脉冲，不是月供。

第二句：**模拟环境验证架构，真实环境验证工程细节**。test-site 的 variant=b 改版开关是全套演示和 E2E 的地基——W2 投入一次，后面全部复用；但真实站点的坑一个都替你挡不了。两套都要有，顺序不能反。

第三句：**演示基建是复利**。改版开关、踢下线接口、版本链 diff、交互时间线页——这些"演示资产"最后都变成了测试资产和分享资产。
