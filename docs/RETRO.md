## 3. 架构决策复盘

### 3.1 做对了的

| 决策 | 理由与回报 |
|------|-----------|
| **Playbook-first，LLM 兜底** | 对比纯 LLM Agent：每次运行都是脉冲成本 vs 持续成本。沉淀机制让"花钱"只发生在页面变化的那一次 |
| **DOM 压缩 + ref 短 ID，非纯视觉坐标** | LLM 引用 `k23` 而非 (x,y)，规避视觉漂移；截图仍作双通道输入，语义 + 视觉互为校验 |
| **选择器 4 层 fallback（css→xpath→text→role/label）** | text 层可交互元素优先（button/a/input），修掉了"登录"匹配 h1 标题的经典坑 |
| **失败四分类 E1-E4 + EX** | 分类驱动行为：EX 配置错直接终止不触发兜底，E1 元素定位失败才是 Agent 主战场 |
| **恢复点评分制（URL 30 / selector 50 / text 20）** | 开发中发现设计缺口：assert-only 步骤 textContains 命中即 50 分，否则永远到不了阈值——设计评审时没看出来的边界 |
| **沉淀 css+text 双保险 + dialog:accept + 剥离 include** | v2 不是 Agent 轨迹的复读，而是蒸馏后的可维护 YAML；include 剥离避免登录二次展开 |
| **防失控三闸（接管 ≤3 次 / ≤15 步 / $0.10）** | Agent 失控的兜底成本上限明确，敢放进生产链路 |
| **请求级 LLM overrides** | Web 用户自带 Key 只活在请求内存，不污染服务端 .env——多租户前提 |

### 3.2 有代价的 / 不足的

| 问题 | 影响 | 反思 |
|------|------|------|
| 蒸馏只做"原位替换" | Agent 若绕路（多步迂回），v2 会比 v1 更长而不是更短 | v1.x 需要"轨迹最短化"：合并、去重、删除无效中间步 |
| 单进程内存版任务表（Web 后端） | 重启丢历史任务；并发无队列 | 演示够用，生产需持久化 + 队列。当时明确不为此加 DB，是对的 |
| 无真实站点验证 | 全部场景跑在自研 test-site | 改版模式是模拟的（按钮改名 + confirm），真实世界改版更杂（iframe/shadow DOM/懒加载）。**W9 已首试真实站点，暴露 3 个 bug，见 §8** |
| 恢复点窗口固定 5 步 | 大跨度改版（失败点与恢复点相距 >5 步）兜底后接不回去 | 可按失败步之后的步骤数动态扩展 |
| LLM 单模型依赖 | qwen3.8-max 网关抖动直接瘫痪 STATE B | CostTracker 已按模型分价，缺自动降级链（qwen3.8-max → glm-5.2 → deepseek-v4-pro） |

## 4. 数据与验收

### 4.1 成本模型实测（qwen3.8-max，单价 $1.6/$6.4 每 1M tokens）

| 场景 | LLM 调用 | Tokens | 成本 | 耗时 |
|------|---------|--------|------|------|
| STATE A 稳定运行（50 SKU） | 0 | 0 | **$0** | 22.6s |
| STATE A v2 沉淀后 | 0 | 0 | **$0** | 2.6s |
| A→B→A 自愈（demo-reprice） | 2 | 8,744 | $0.0417 | 112.9s* |
| 纯 Agent 全链路（登录+改价） | 8 | 15,438 | $0.0276 | 18.7s |
| 纯 Agent（Web 控制台提交） | 8 | 15,438 | $0.0276 | — |

*112.9s 中 Agent 仅 2 步，大头是感知器截图 + DOM 采集 + 思考型模型的 reasoning token（输出 5,772 > 输入 2,972，思考型模型输出贵 4 倍是成本主因）。

**结论**：一次自愈 $0.04 ≈ 等于 5 次 Starbucks WiFi，换回一条不再需要人工修的 Playbook。按"改版一次摊销"计算，LLM 成本可以忽略。

### 4.2 工程质量

- F-01 加载性能 3.03ms/次（标准 <100ms）；F-02 十次运行一致率 100%、heap 25MB
- MVP 验收 22 条全部通过（docs/MVP-ACCEPTANCE.md）
- E2E 覆盖关键链路：variant=b 改版自愈、session 踢线重登、域名白名单安全约束、learn 蒸馏闭环

## 5. 踩坑精选（全量 27 见 SHARING.md）

按"通用可迁移"价值排序：

1. **zod discriminatedUnion 不接受任何 refine/z.lazy 包装成员** —— 跨字段约束必须放语义后置层；递归类型用 `Extract<Step, {action:'loop'}>` 派生而非显式注解。类型系统的问题 tsc 不报，运行时才炸。
2. **page.evaluate 传函数引用，模块作用域全 undefined** —— 函数体会被序列化到页面执行，必须自包含内联。连踩三次（主函数/常量/参数化调用）。
3. **Playwright 默认 dismiss confirm()** —— Agent 反复点"确认下单"看似成功实际被取消。`page.on('dialog', accept)` 一行解决，但排查了一小时。
4. **思考型模型连排输出双 JSON** —— `lastIndexOf('}')` 截取出 `{..}{..}` 无法 parse。改括号配对扫描（字符串转义感知）。
5. **单步批跑 Agent 每步重发完整上下文** —— 14s+/步。改 onAfterAction 钩子挂主循环，一次对话上下文内完成恢复点检查。
6. **vitest 默认 hookTimeout 10s** —— 多 chromium 并行挤爆 beforeAll，连环误报。全局 hookTimeout 120s + testTimeout 300s。
7. **zod default 丢失**：include 展开消费了原始 YAML 而非 parse 后数据。铁律：**有 default 的字段，下游必须消费 parse 后的数据**。
8. **真实站点三连坑（#25/#26/#27）**：导航销毁执行上下文、模型吐 DSML 而非 JSON、截图卡字体加载 30s。共同病根是**相信了默认行为**——凡跨外部资源或页面跳转的调用，一律显式超时 + 降级路径，且这类问题本地 test-site 一个都复现不了。

## 8. W9 补记：真实站点首轮实战（2026-09-14）

> 本章为 W8 复盘之后的首轮真实站点实战补记，不改前面 W1–W8 的结论。

### 8.1 做了什么

- **环境从零重建**：npm 162 包（npmmirror）+ Chromium 129（镜像 22s）+ 三服务联跑（test-site 3456 / API 4567 / Web 5173），`tsc --noEmit` 零错误
- **LLM 换血**：qwen3.8-max → **deepseek-flash**（官方现名；`deepseek-v4-flash` 是已下线模型的别名，实测仍可用并自动映射）
- **真实站点（百度）跑 Agent**，暴露并修复 3 个 bug（SHARING #25/#26/#27）

### 8.2 真实站点三连坑

| # | 问题 | 病根 | 修复 |
|---|------|------|------|
| 25 | 点击触发导航 → `Execution context was destroyed`，任务判失败 | 感知器跑在旧页面上下文上，无重试 | `snapshot()` 整批重试（退避 3 次）+ 动作后 250ms 沉降 |
| 26 | 模型吐 DSML 工具调用标记而非 JSON | 假定模型一定输出 JSON | 请求侧 `jsonMode` + 解析侧 DSML 兼容 + 失败重试（回传坏输出自我纠正） |
| 27 | 截图卡 `waiting for fonts to load` 超时 30s | 用了默认 30s 超时，且字体等待无法关闭 | 三级降级：6s 超时 → CDP 直取 → 空截图纯 DOM 决策 |

**共同病根**：三个都是**相信了默认行为**——默认无重试、默认输出 JSON、默认 30s 超时。且**三个在本地 test-site 全部复现不了**。

### 8.3 关键结论

1. **test-site 验证架构，真实站点验证工程细节**——W8 的判断成立，代价是 3 个 bug。今后新编写的外部调用，默认带「显式超时 + 降级路径」
2. **换模型必须实测两项**：纯文本 + **带截图**。`/api/health` 只证明配置读到了，证明不了模型支持视觉。中间件 mimo-v2.5-pro 就是纯文本 200、带图 404——接进来 Agent 模式直接废（对比：deepseek-flash 两项都通，1s 级响应）
3. **模型输出格式不可信**：解析环节三件套（请求侧约束 + 解析侧兼容 + 失败重试）；把坏输出回传让模型自我纠正，比单纯重复请求有效

### 8.4 模型与成本

- 单价按官方 CNY 价 ÷ 汇率（6.7698）折算，取「空闲时段 + 缓存未命中」档（每轮带新截图，输入基本走未命中档），口径已写入 `llm.ts` 注释
- deepseek-flash 实测：登录任务 4 步、4 次 LLM 调用、4,356 tokens、**$0.0007**；相比 qwen3.8-max 同场景约 $0.028，**成本降一个量级**（主要来自单价而非 token 数）
- 顺带修正：`deepseek-v4-pro` 单价此前是估值，已按官方价更新

| 问题 | 等级 | 说明 |
|------|------|------|
| 无头 Chromium 被反爬识别（百度滑块验证码） | 中 | Agent 动作集无拖拽，只能判 fail；有头模式可能规避。需新增 drag/鼠标轨迹动作 |
